sleepv — это скрипт-обёртка над стандартной командой sleep.

Стандартная команда sleep просто делает паузу — без какого-либо вывода.
Вы запускаете "sleep 5m" и сидите, не зная: скрипт завис или честно ждёт.

sleepv решает эту проблему: во время паузы в терминале отображается
живой прогресс-бар с обратным отсчётом.

Пример того, что вы видите в терминале:

  ⏱  00:01:23  [████████████░░░░░░░░░░░░░░░░░░]   58%  (2m 3s)

Здесь:
  • 00:01:23 — сколько времени осталось до конца паузы (HH:MM:SS)
  • [████░░░░] — визуальный прогресс-бар (заполняется по мере истечения)
  • 58%       — процент прошедшего времени
  • (2m 3s)  — исходный аргумент, который вы передали

Когда пауза завершается:
  ✓  Готово! (было: 2m 3s)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Шаг 1. Сделайте файл исполняемым
─────────────────────────────────
    chmod +x sleepv

Шаг 2. Установите в систему (чтобы команда была доступна отовсюду)
────────────────────────────────────────────────────────────────────
    ./sleepv --install

Скрипт сам скопирует себя в /usr/sbin/sleepv и выставит нужные права.
Если у вашего пользователя недостаточно прав — он автоматически запросит sudo.

Что произойдёт при --install:
  1. Скрипт определяет своё текущее расположение
  2. Копирует себя в /usr/sbin/sleepv (всегда с именем "sleepv")
  3. Устанавливает права на выполнение: chmod +x
  4. Если прав не хватает — пробует через sudo
  5. Если и sudo не помогло — выводит инструкцию для ручной установки

После установки команда sleepv доступна из любого места в системе,
из любого терминала и из любого скрипта — так же, как обычный sleep.

Проверка установки:
    which sleepv
    # Должно вывести: /usr/sbin/sleepv

Удаление (если понадобится):
    sudo rm /usr/sbin/sleepv

    sleepv ЧИСЛО[СУФФИКС] [ЧИСЛО[СУФФИКС] ...]

СУФФИКСЫ:
┌─────────┬──────────────┬────────────────────┐
│ Суффикс │ Значение     │ Пример             │
├─────────┼──────────────┼────────────────────┤
│ s       │ секунды      │ sleepv 30s         │
│ m       │ минуты       │ sleepv 5m          │
│ h       │ часы         │ sleepv 2h          │
│ d       │ дни          │ sleepv 1d          │
│ (нет)   │ секунды      │ sleepv 90          │
└─────────┴──────────────┴────────────────────┘

Несколько аргументов суммируются:
    sleepv 1m 30s     → пауза 90 секунд
    sleepv 1h 5m 3s   → пауза 3903 секунды (1 час 5 минут 3 секунды)
    sleepv 2d 12h     → пауза 2.5 суток

Дробные числа тоже поддерживаются:
    sleepv 1.5m       → пауза 90 секунд
    sleepv 0.5h       → пауза 30 минут

    sleepv 10

── Паузы в минутах ──────────────────────────────────────────────────────────

    sleepv 5m
    sleepv 2.5m

    Пауза 5 минут. Второй пример — 2 минуты 30 секунд.

── Паузы в часах ────────────────────────────────────────────────────────────

    sleepv 1h
    sleepv 0.5h

    Пауза 1 час. Второй пример — 30 минут.

    sleepv 1h 30m
    sleepv 2m 45s
    sleepv 1d 6h 30m

    Аргументы суммируются слева направо.
    Первый пример: 1 час 30 минут = 5400 секунд.

    sleepv --version

    Выводит версию sleepv и версию системного GNU sleep.

    ./sleepv --install

    После этого команда доступна глобально.

sleepv — прямая замена sleep. Достаточно написать sleepv вместо sleep.
Совместимость гарантирована: синтаксис полностью идентичен.

Пример фрагмента скрипта:

    #!/bin/bash
    echo "Ждём 30 секунд перед запуском..."
    sleepv 30s

    echo "Пауза на 5 минут..."
    sleepv 5m

    echo "Продолжаем работу."

── Как sleepv ведёт себя в разных контекстах ────────────────────────────────

1. В терминале (интерактивный режим):
   Отображается прогресс-бар, таймер и процент. Это основной режим.

2. В скрипте без терминала (cron, systemd, фоновый запуск):
   sleepv автоматически определяет, что терминала нет, и молча вызывает
   обычный sleep. Никакого лишнего вывода. Скрипт работает как прежде.

3. В конвейере (pipe):
       sleepv 5s | другая_команда
   stdout абсолютно чист. Прогресс идёт в stderr и не мешает данным.

4. В подстановке команд:
       result=$(sleepv 5s; echo "данные")
   Переменная result получит только "данные". Прогресс в stdout не попадает.

5. При перенаправлении stderr в /dev/null:
       sleepv 5s 2>/dev/null
   Пауза произойдёт тихо, прогресс-бар не выводится.

── Отмена паузы ─────────────────────────────────────────────────────────────

Нажмите Ctrl+C — пауза прервётся, скрипт завершит работу.
Курсор в терминале будет корректно восстановлен.
Код возврата при прерывании: 130 (стандарт для Ctrl+C).

── Пример 1: Ожидание после перезапуска сервиса ─────────────────────────────

    systemctl restart networking
    echo "Ждём поднятия сети..."
    sleepv 15s
    ping -c 3 8.8.8.8

── Пример 2: Пауза между попытками подключения ──────────────────────────────

    for i in 1 2 3; do
        echo "Попытка $i..."
        connect_to_server && break
        echo "Неудача. Следующая попытка через 30 секунд."
        sleepv 30s
    done

── Пример 3: Регулярная задача с паузой между итерациями ────────────────────

    while true; do
        check_status
        echo "Следующая проверка через 5 минут."
        sleepv 5m
    done

── Пример 4: Отладка — видеть, что скрипт не завис ─────────────────────────

    echo "Завершение процессов..."
    kill -TERM "$some_pid"
    sleepv 3s          # Видно, что скрипт ждёт — не завис!
    kill -KILL "$some_pid"

── Пример 5: Предупреждение перед опасным действием ─────────────────────────

    echo "ВНИМАНИЕ! Форматирование начнётся через 10 секунд. Ctrl+C для отмены."
    sleepv 10s
    mkfs.ext4 /dev/sdX

── Пример 6: Использование в cron (тихий режим) ─────────────────────────────

    # В crontab — sleepv не будет выводить ничего лишнего:
    */5 * * * * /usr/sbin/goinet && sleepv 30s && /usr/sbin/другой_скрипт

Требования:
  • bash версии 4.0 и выше (стандартный в Debian/Raspberry Pi OS/Kali)
  • GNU sleep (входит в пакет coreutils — всегда есть в системе)
  • bc или awk (для вычислений — оба есть в любом Debian по умолчанию)
  • tput (для управления курсором — входит в пакет ncurses-bin)

Проверить наличие зависимостей:
    which bash sleep bc awk tput

Поддерживаемые оболочки для вызова:
  ✓ bash    (полная поддержка)
  ✓ sh      (вызов через sh работает, т.к. bash совместим)
  ✓ dash    (вызов работает — shebang указывает на bash)
  ✓ zsh     (вызов как внешней команды работает полностью)

Поддерживаемые терминалы:
  ✓ xfce4-terminal
  ✓ xterm
  ✓ lxterminal
  ✓ gnome-terminal
  ✓ konsole
  ✓ SSH-сессии
  ✓ tmux / screen (прогресс отображается корректно)
  ✓ Вызов из скриптов без терминала (тихий режим)

Единственный сценарий где прогресс может попасть в данные:
  Если ваш скрипт делает:  output=$(команда_вызывающая_sleepv 2>&1)
  Тогда строка прогресса попадёт в переменную output через 2>&1.
  Решение: добавить 2>/dev/null к вызову sleepv внутри такой команды.
  Но это редкий случай — обычные скрипты с этим не сталкиваются.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Как работает обнаружение терминала:
  Команда [[ -t 2 ]] проверяет, привязан ли stderr к TTY (терминалу).
  Если да — включается визуальный режим.
  Если нет (cron, pipe, фон) — запускается оригинальный sleep напрямую.

Как работает прогресс-бар:
  Каждую секунду скрипт перезаписывает текущую строку терминала с помощью
  escape-последовательности \r (возврат каретки) и \033[K (очистка строки).
  Это значит, что прогресс всегда на одной строке — не "прокручивает" экран.

Точность паузы:
  Оригинальный sleep запускается параллельно в фоне.
  Визуальный отсчёт работает поверх него отдельно.
  Итоговая точность паузы — та же, что у системного sleep.
  Визуальный счётчик считает с погрешностью ±1 секунда (это норма).

Где находится прогресс-бар в потоках вывода:
  stdout (поток 1) — чистый, как у оригинального sleep
  stderr (поток 2) — прогресс-бар и таймер

Поведение при Ctrl+C:
  Скрипт перехватывает сигнал INT, завершает фоновый sleep,
  восстанавливает курсор (tput cnorm) и выходит с кодом 130.
