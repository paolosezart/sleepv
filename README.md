# sleepv

Визуальный обратный отсчёт перед паузой. Проект содержит две отдельные реализации:

- **Linux:** Bash-скрипт версии 1.0 (`sleepv`).
- **Windows:** нативная Win32-программа версии 1.1.0 (`sleepv-x86.exe` и `sleepv-x64.exe`), рассчитанная на Windows Vista SP2 и новее.

Документация на английском: [README-EN.md](README-EN.md).

## Релизы и загрузка

Откройте [GitHub Releases](https://github.com/paolosezart/sleepv/releases). В последующих релизах, создаваемых из версии репозитория с обновлённым workflow, будут публиковаться три исполняемых файла и общий файл контрольных сумм:

- `sleepv-linux` — исходный Bash-скрипт для Linux;
- `sleepv-x86.exe` — Windows x86;
- `sleepv-x64.exe` — Windows x64;
- `SHA256SUMS.txt` — SHA-256 всех трёх файлов.

Старые Releases workflow задним числом не изменяет. В Linux сохраните `sleepv-linux`, затем выполните:

```sh
chmod +x sleepv-linux
./sleepv-linux 30s
```

Проверка SHA-256 на Linux:

```sh
sha256sum -c SHA256SUMS.txt
```

На Windows контрольную сумму можно проверить, например, так:

```powershell
Get-FileHash .\sleepv-x64.exe -Algorithm SHA256
```

## Как пользоваться

Обычный вызов ждёт заданное время. Если stderr подключён к терминалу, показывается обратный отсчёт; в неинтерактивном режиме пауза выполняется без прогресс-бара. `stdout` остаётся свободным для данных, прогресс выводится в `stderr`.

```sh
sleepv 30       # 30 секунд
sleepv 30s      # то же
sleepv 5m       # 5 минут
sleepv 1h 30m   # сумма аргументов: 1 час 30 минут
sleepv 1.5m     # 90 секунд (Linux: цифры до десятичной точки обязательны)
```

Суффиксы `s`, `m`, `h`, `d` означают секунды, минуты, часы и дни; без суффикса значение задаётся в секундах. Аргументы длительности суммируются. Отрицательные значения и неподдерживаемые суффиксы не принимаются.

## Linux

### Установка

Для запуска скачанного файла:

```sh
chmod +x sleepv-linux       # либо chmod +x sleepv, если взяли файл из репозитория
./sleepv-linux --install
```

`--install` копирует скрипт в `/usr/sbin/sleepv`; при нехватке прав скрипт пытается использовать `sudo`. Для удаления установленного файла используйте `sudo rm /usr/sbin/sleepv`. Linux-версия не имеет параметров `--dir` и `--uninstall`.

### Команды и параметры Linux

```text
sleepv NUMBER[SUFFIX] [NUMBER[SUFFIX] ...]
sleepv --help | -h
sleepv --version
sleepv --install
```

- `--help` / `-h` показывает справку, в том числе справку найденной системной команды `sleep`.
- `--version` показывает версию скрипта и, если найден, версию системного `sleep`.
- `--install` устанавливает скрипт в `/usr/sbin/sleepv`.
- Иных опций, включая Windows-опции, Linux-скрипт не поддерживает.

### Совместимость и точность

Скрипт использует Bash (`#!/usr/bin/env bash`), системную команду `sleep` и `bc` либо `awk` для арифметики. `tput` используется лишь для управления видимостью курсора и не является обязательным. Запускайте скрипт как исполняемый файл (`./sleepv`), а не передавайте его интерпретатору `sh` или `dash`.

Linux-парсер принимает десятичное число только с цифрой перед точкой: `1.5s` допустимо, `.5s` — нет. Для отображения длительность суммируется и округляется вниз до целых секунд. Поэтому субсекундная длительность в интерактивном терминале может завершиться сразу, а отображаемый отсчёт для дробных секунд не является точным. В неинтерактивном режиме скрипт передаёт исходные аргументы найденной системной команде `sleep`; фактическая поддержка дробей в этом режиме зависит от неё. Формального максимума длительности в скрипте нет.

В интерактивном терминале Ctrl+C прерывает скрипт с кодом 130 и восстанавливает курсор (если терминал поддерживает `tput`). В неинтерактивном режиме управление передаётся системному `sleep`, поэтому поведение сигнала определяется вызывающей средой и этой командой.

## Windows

Windows-версия — нативное приложение Win32, а не Bash- или PowerShell-скрипт. Оно статически слинковано и не требует .NET или Visual C++ Redistributable. Поддерживаемая минимальная версия — Windows Vista SP2.

- `sleepv-x86.exe` — 32-разрядная сборка; может запускаться на 64-разрядной Windows через эмуляцию.
- `sleepv-x64.exe` — 64-разрядная сборка.
- Достаточно скачать exe и запустить его; установка не обязательна.

### Установка Windows

```cmd
sleepv-x64.exe --install
sleepv-x64.exe --install --dir "D:\tools"
sleepv-x64.exe --uninstall
```

`--install` копирует файл в системный каталог Windows и запрашивает UAC при необходимости. `--install --dir PATH` устанавливает в указанную папку, создавая её при необходимости; добавление этой папки в `PATH` остаётся за пользователем. `--uninstall` удаляет установленные системные копии и требует прав администратора.

### Параметры Windows

| Параметр | Действие |
| --- | --- |
| `--help`, `-h` | Показать справку. |
| `--version` | Показать версию, целевую ОС, разрядность и сведения о сборке. |
| `--install [--dir PATH]` | Установить exe в системный каталог либо в указанную папку. |
| `--uninstall` | Удалить системные копии. |
| `--run "COMMAND"` | Добавить команду в очередь после паузы; параметр можно повторять. |
| `-a`, `--after` | Ждать завершения команд `--run`; действует также на непосредственно предыдущую команду и на следующие. |
| `-w`, `--workdir PATH` | Задать начальный рабочий каталог для следующих `--run`; значение наследуется, пока не задано новое. Требуется хотя бы один `--run`. |
| `--beep` | Подать короткий звуковой сигнал после интерактивного отсчёта; в тихом режиме сигнал не подаётся. |
| `--msg [TEXT]` | Показать окно после отсчёта; без текста используется стандартное сообщение. |
| `--ascii` | Нарисовать прогресс-бар символами `#` и `-`. |
| `--unicode` | Использовать блочные символы прогресс-бара. |
| `-q`, `--quiet` | Не выводить обычный прогресс, сообщение о завершении и сигнал. Не подавляет ошибки, окно `--msg` или вывод дочерних команд. |
| `--strict-cancel` | При Ctrl+C вернуть код 130 вместо 0. |

Если задаёте текст `--msg`, поставьте все аргументы времени перед ним: непосредственно следующий аргумент, если он не начинается с `-`, будет воспринят как текст окна. Окно появляется после отсчёта и до запуска очереди.

```cmd
sleepv-x64.exe 14s --msg Complete --run quser
sleepv-x64.exe 14s -a --msg Complete --run quser --after --run ver --run "echo done"
sleepv-x64.exe 5s -w "C:\Projects\demo" --run "dir && echo done"
sleepv-x64.exe 5m --beep --msg
sleepv-x64.exe 30s --msg 765
```

По умолчанию `--run` запускает процессы асинхронно: `sleepv` не ждёт их завершения и не может вернуть их будущий код выхода. `-a` / `--after` включает ожидание для предыдущей команды (если она есть) и всех следующих; ожидаемые команды выполняются последовательно. Код последней ожидаемой команды становится кодом `sleepv`; если последняя команда запущена асинхронно, `sleepv` обычно завершается с кодом 0 после её запуска.

`-w` / `--workdir` задаёт каталог, с которого стартует соответствующий процесс, и наследуется последующими элементами очереди до нового `--workdir`. `cd` внутри одной команды `--run` может менять каталог для последующих частей этой же строки, но не меняет стартовый каталог следующих процессов очереди.

Каждый `--run` выполняется через `cmd.exe`; поэтому внутри строки команды доступны стандартные операторы CMD `&&`, `&`, `|` и `||`. Они принадлежат CMD, а не являются операторами самого `sleepv`.

### Отмена и тихий режим Windows

Ctrl+C отменяет отсчёт. По умолчанию программа возвращает 0; с `--strict-cancel` возвращает 130. При отмене окно `--msg` не показывается, а команды очереди не запускаются. Если stderr не является консолью, прогресс автоматически не выводится. `--quiet` также подавляет обычный экранный вывод, но не ошибки, диалоговое окно или вывод запущенных команд.

## Отличия Linux и Windows

| Возможность | Linux Bash | Windows exe |
| --- | --- | --- |
| Дробное число | Перед точкой обязательна цифра; визуальный расчёт округляет сумму вниз до целых секунд. | Поддерживаются дробные значения, в том числе `.5`; таймер учитывает дробную часть. |
| Максимум | В скрипте формальный предел не задан. | 30 суток; превышение отклоняется. |
| Дополнительные действия после паузы | Нет специальных опций. Последовательность `sleepv ... && command` обрабатывает внешняя оболочка. | Есть очередь `--run`, режим ожидания `--after`, рабочий каталог, окно сообщения и другие параметры. |
| Ctrl+C | Код 130 в интерактивном режиме; без терминала сигнал обрабатывает системный `sleep`/вызывающая среда. | Код 0 по умолчанию; `--strict-cancel` задаёт код 130. Очередь при отмене не запускается. |
| Прогресс | Заполняется оставшееся время и уменьшается. Обновление примерно раз в секунду. | Заполняется прошедшее время и растёт. Обновление примерно 10 раз в секунду. |
| Текст | Русский UTF-8. | Сообщения программы на английском; доступен ASCII-бар, а блочные символы зависят от режима/консоли. |

Это две реализации с пересекающимся, но не идентичным синтаксисом; полной совместимости со всеми вариантами GNU `sleep` нет. Windows-опции (`--run`, `--workdir`, `--msg` и другие) не работают в Linux-скрипте.

## Сборка и автоматические проверки

Windows-сборки можно создать из Linux с MinGW-w64 или из MSYS2/MinGW:

```sh
sudo apt-get install mingw-w64 binutils-mingw-w64
make -C win all
make -C win gate
```

GitHub Actions собирает x86 и x64, проверяет таблицу импортов на запрещённые зависимости и ограничивает размер каждого exe. Отдельный smoke-тест под Wine проверяет отдельные варианты парсера, кодов возврата, очереди команд и установки, но он помечен как **неблокирующий** (`continue-on-error`): успешный Wine-тест не является обязательным условием публикации. При создании релиза по тегу `v*` workflow прикладывает Linux-скрипт, обе Windows-сборки и `SHA256SUMS.txt`; SHA-256 файлов также включаются в заметки релиза.
