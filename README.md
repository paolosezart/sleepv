sleepv — это скрипт-обёртка над стандартной командой sleep.

Стандартная команда sleep просто делает паузу — без какого-либо вывода.
Вы запускаете "sleep 5m" и сидите, не зная: скрипт завис или честно ждёт.

sleepv решает эту проблему: во время паузы в терминале отображается
живой прогресс-бар с обратным отсчётом.

Пример того, что вы видите в терминале:

  ⏱  00:01:23  [████████████░░░░░░░░░░░░░░░░░░]   58%  (2m 3s)

Здесь:
  • 00:01:23 — сколько времени осталось до конца паузы (HH:MM:SS)
  • [████░░░░] — прогресс-бар: закрашенная часть = сколько ОСТАЛОСЬ ждать
    (в Linux-версии полоса уменьшается, в Windows-версии — растёт, см. раздел
    «Отличия Windows-версии»)
  • 58%       — процент прошедшего времени
  • (2m 3s)  — исходный аргумент, который вы передали

Когда пауза завершается:
  ✓  Готово! (было: 2m 3s)

Шаг 1. Сделайте файл исполняемым
─────────────────────────────────
    chmod +x sleepv

Шаг 2. Установите в систему (чтобы команда была доступна отовсюду)
────────────────────────────────────────────────────────────────────
    ./sleepv --install

Скрипт сам скопирует себя в /usr/sbin/sleepv и выставит нужные права.
Если у вашего пользователя недостаточно прав — он автоматически запросит sudo.

Что произойдёт при --install:
  1. Скрипт определяет своё текущее расположение
  2. Копирует себя в /usr/sbin/sleepv (всегда с именем "sleepv")
  3. Устанавливает права на выполнение: chmod +x
  4. Если прав не хватает — пробует через sudo
  5. Если и sudo не помогло — выводит инструкцию для ручной установки

После установки команда sleepv доступна из любого места в системе,
из любого терминала и из любого скрипта — так же, как обычный sleep.

Проверка установки:
    which sleepv
    # Должно вывести: /usr/sbin/sleepv

Удаление (если понадобится):
    sudo rm /usr/sbin/sleepv

Общий вид команды:

    sleepv ЧИСЛО[СУФФИКС] [ЧИСЛО[СУФФИКС] ...]

СУФФИКСЫ:
┌─────────┬──────────────┬────────────────────┐
│ Суффикс │ Значение     │ Пример             │
├─────────┼──────────────┼────────────────────┤
│ s       │ секунды      │ sleepv 30s         │
│ m       │ минуты       │ sleepv 5m          │
│ h       │ часы         │ sleepv 2h          │
│ d       │ дни          │ sleepv 1d          │
│ (нет)   │ секунды      │ sleepv 90          │
└─────────┴──────────────┴────────────────────┘

Несколько аргументов суммируются:
    sleepv 1m 30s     → пауза 90 секунд
    sleepv 1h 5m 3s   → пауза 3903 секунды (1 час 5 минут 3 секунды)
    sleepv 2d 12h     → пауза 2.5 суток

Дробные числа тоже поддерживаются:
    sleepv 1.5m       → пауза 90 секунд
    sleepv 0.5h       → пауза 30 минут

── Обычная пауза (секунды) ──────────────────────────────────────────────────

    sleepv 10

    Пауза ровно 10 секунд. Суффикс 's' можно не писать.

── Паузы в минутах ──────────────────────────────────────────────────────────

    sleepv 5m
    sleepv 2.5m

    Пауза 5 минут. Второй пример — 2 минуты 30 секунд.

── Паузы в часах ────────────────────────────────────────────────────────────

    sleepv 1h
    sleepv 0.5h

    Пауза 1 час. Второй пример — 30 минут.

    sleepv 1h 30m
    sleepv 2m 45s
    sleepv 1d 6h 30m

    Аргументы суммируются слева направо.
    Первый пример: 1 час 30 минут = 5400 секунд.

    sleepv --version

    Выводит версию sleepv и версию системного GNU sleep.

    ./sleepv --install

sleepv — прямая замена sleep. Достаточно написать sleepv вместо sleep.
Совместимость гарантирована: синтаксис полностью идентичен.

Пример фрагмента скрипта:

    #!/bin/bash
    echo "Ждём 30 секунд перед запуском..."
    sleepv 30s

    echo "Пауза на 5 минут..."
    sleepv 5m

    echo "Продолжаем работу."

── Как sleepv ведёт себя в разных контекстах ────────────────────────────────

1. В терминале (интерактивный режим):
   Отображается прогресс-бар, таймер и процент. Это основной режим.

2. В скрипте без терминала (cron, systemd, фоновый запуск):
   sleepv автоматически определяет, что терминала нет, и молча вызывает
   обычный sleep. Никакого лишнего вывода. Скрипт работает как прежде.

3. В конвейере (pipe):
       sleepv 5s | другая_команда
   stdout абсолютно чист. Прогресс идёт в stderr и не мешает данным.

4. В подстановке команд:
       result=$(sleepv 5s; echo "данные")
   Переменная result получит только "данные". Прогресс в stdout не попадает.

5. При перенаправлении stderr в /dev/null:
       sleepv 5s 2>/dev/null
   Пауза произойдёт тихо, прогресс-бар не выводится.

── Отмена паузы ─────────────────────────────────────────────────────────────

Нажмите Ctrl+C — пауза прервётся, скрипт завершит работу.
Курсор в терминале будет корректно восстановлен.
Код возврата при прерывании: 130 (стандарт для Ctrl+C).

── Пример 1: Ожидание после перезапуска сервиса ─────────────────────────────

    systemctl restart networking
    echo "Ждём поднятия сети..."
    sleepv 15s
    ping -c 3 8.8.8.8

── Пример 2: Пауза между попытками подключения ──────────────────────────────

    for i in 1 2 3; do
        echo "Попытка $i..."
        connect_to_server && break
        echo "Неудача. Следующая попытка через 30 секунд."
        sleepv 30s
    done

── Пример 3: Регулярная задача с паузой между итерациями ────────────────────

    while true; do
        check_status
        echo "Следующая проверка через 5 минут."
        sleepv 5m
    done

── Пример 4: Отладка — видеть, что скрипт не завис ─────────────────────────

    echo "Завершение процессов..."
    kill -TERM "$some_pid"
    sleepv 3s          # Видно, что скрипт ждёт — не завис!
    kill -KILL "$some_pid"

── Пример 5: Предупреждение перед опасным действием ─────────────────────────

    echo "ВНИМАНИЕ! Форматирование начнётся через 10 секунд. Ctrl+C для отмены."
    sleepv 10s
    mkfs.ext4 /dev/sdX

── Пример 6: Использование в cron (тихий режим) ─────────────────────────────

    # В crontab — sleepv не будет выводить ничего лишнего:
    */5 * * * * /usr/sbin/goinet && sleepv 30s && /usr/sbin/другой_скрипт

 WINDOWS-ВЕРСИЯ (Vista SP2 и новее)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Это НЕ перенос bash-скрипта и не обёртка над PowerShell. sleepv для Windows —
нативное приложение на Win32 API (win/sleepv.c), статически слинкованное, без
единой внешней зависимости: ни .NET, ни Visual C++ redist, ни PowerShell, ни
GNU coreutils не нужны. Импортируются только kernel32.dll, msvcrt.dll,
user32.dll, shell32.dll и advapi32.dll — все они являются компонентами Windows.

Файлы:
    sleepv-x86.exe     для 32-битных систем и для смешанного парка (работает и
                       на 64-битных Windows, включая ARM64 через эмуляцию)
    sleepv-x64.exe     для 64-битных Windows 7/8/10/11
    ~80-90 КБ каждый

Поддерживаемые системы: Windows Vista SP2, 7, 8, 8.1, 10, 11, серверные
разновидности тех же лет. Ни one-core API вида api-ms-win-* и ни UCRT не
используются — это и есть техническое условие работы на Vista; в CI стоит
автоматическая проверка импорт-таблицы на это.

── Где взять ────────────────────────────────────────────────────────────────

1) Готовый бинарник в дереве репозитория: win/dist/sleepv-x86.exe и
   win/dist/sleepv-x64.exe. Оба файла коммитятся намеренно, чтобы портировать
   утилиту можно было простым клонированием, без Releases и без тулчейна.

2) То же самое во вкладке Releases: релиз собирается GitHub Actions по тегу v*
   и содержит sleepv-x86.exe, sleepv-x64.exe и SHA256SUMS.txt; значения хэшей
   приведены прямо в описании релиза.

3) Портативное использование: скачанный exe можно просто положить в папку с
   вашими .bat-скриптами — установка не обязательна.

4) Собрать самому (кросс-компиляция из Linux или нативно в MSYS2/MinGW):

       sudo apt-get install mingw-w64
       make -C win all
       make -C win gate        # проверка импортов на совместимость с Vista

   ВАЖНО ПРО ХЭШИ. win/dist и ассеты Releases собираются одним и тем же
   Makefile и с одними и теми же флагами, но разными версиями binutils/gcc
   (локальная сборка против сборки на runner'е), поэтому побайтово файлы могут
   не совпадать: SHA256SUMS.txt из релиза относится именно к файлам релиза.
   Поведение от этого не меняется; если нужна гарантия «те же байты», собирайте
   сами из исходников и сверяйте с собственной сборкой.

── Синтаксис времени — тот же, что в Linux ──────────────────────────────────

    sleepv 5m
    sleepv 1h 30m 12.5s
    sleepv 30s && calc

   Суффиксы s/m/h/d, аргументы суммируются, дроби поддерживаются, отрицательные
   значения и «мусорные» хвосты отвергаются. Максимальная пауза — 30 суток.

   Вид в консоли (10 обновлений в секунду, точность — единицы миллисекунд):

      00:04:12  [#############░░░░░░░░░░░░░░░░░░]   33%  (5m)

── Установка для всех пользователей ─────────────────────────────────────────

    sleepv --install

   Программа запросит права администратора через UAC и скопирует себя в
   C:\Windows\System32. Важные детали:

     • 32-битная сборка при обычном записи попала бы в SysWOW64 (File System
       Redirector), поэтому путь строится с префиксом "\\?\" и попадает именно
       в настоящую System32.
     • System32 уже входит в системный PATH, поэтому команда становится доступна
       ВСЕМ пользователям сразу, без редактирования PATH и без перезагрузки —
       достаточно открыть новое окно консоли.
     • Инсталлер проверяет, что BUILTIN\Users имеют Read & Execute на файле, и
       при необходимости дописывает это право явно.
     • В манифесте стоит asInvoker: без него Vista включила бы VirtualStore, и
       «установка» тихо улетела бы в %LOCALAPPDATA% вместо System32.

   Дополнительно:

       sleepv --install --dir "D:\tools"    # любая своя папка, без UAC;
                                            # недостающие уровни каталога создаются,
                                            # о том, что папка не в PATH, - предупреждение
       sleepv --uninstall                   # удалить копии (нужен админ)

── Только для Windows: список опций ──────────────────────────────────────────

    --install [--dir PATH]   скопировать себя в системную папку (UAC)
    --uninstall              удалить установленные копии
    --run "КОМАНДА"          выполнить команду после паузы, вернуть её код
    --beep                   звуковой сигнал по завершении
    --msg                    всплывающее окно по завершении
    --ascii                  бар из # и - (авто по умолчанию на Vista/2008)
    --unicode                бар из блочных символов (по умолчанию на Win7+)
    --strict-cancel          код 130 при Ctrl+C (останавливает цепочку &&)
    -q, --quiet              полностью без вывода
    --help, --version        справка / версия и параметры сборки

   Примеры:

       sleepv 30s --run "ipconfig /all"
       sleepv 5m --beep --msg
       for /L %%i in (1,1,5) do ( echo try %%i & sleepv 10s )

── Поведение в .bat / cmd / PowerShell ──────────────────────────────────────

   Тихий режим без консоли идентичен Linux: если stderr не является консолью
   (служба, планировщик задач, перенаправление, pipe) — пауза проходит молча,
   stdout остаётся чистым, прогресс пишется в stderr.

   Ctrl+C. Прерывание завершает отсчёт и возвращает код 0, поэтому следующий
   оператор в .bat-файле продолжает выполняться, а cmd.exe не показывает
   «Terminate batch job (Y/N)?» (этот запрос появляется только когда дочерний
   процесс вернул 0xC000013A). Если вам нужно наоборот — остановить цепочку,
   запустите с --strict-cancel: тогда код будет 130.

   Единственная оговорка: в самом PowerShell Ctrl+C прерывает конвейер по
   правилам самой оболочки, и дочерний процесс на это повлиять не может. Если
   внутри .ps1 нужно продолжить работу после прерывания паузы, вызывайте так:
   cmd /c "sleepv 30s && следующая_команда".

── Отличия Windows-версии от Linux-скрипта (подробно) ───────────────────────

   Linux-скрипт версии 1.0 намеренно НЕ изменён: порт живёт рядом, все расхождения
   задокументированы здесь. Проверено на: bash 5.2.15, GNU coreutils sleep 9.1,
   wine-8.0 (для запуска exe из-под Linux). Коды возврата и сообщения снимались
   фактическими запусками, команды проверки — в конце раздела.

   1. ТОЧНОСТЬ И ЧАСТОТА ОБНОВЛЕНИЯ
      Linux: цикл с квантом 1 с поверх фонового sleep. Бар и таймер обновляются
             раз в секунду, суммарный дрейф отсчёта ~18 мс на итерацию, то есть за
             час визуально возможно отставание в одну секунду.
      Windows: абсолютный дедлайн по QueryPerformanceCounter, перерисовка 10 раз
             в секунду, дрейф единичные миллисекунды.
      Практический смысл: если бар используют как « proof of life », обе версии
      корректны; если нужен точный таймер — Windows точнее, Linux в любом случае
      делегирует саму паузу системному sleep, поэтому фактическая длительность
      паузы у обеих версий одинаково точна.

   2. НАПРАВЛЕНИЕ И ГРАФИКА ПРОГРЕСС-БАРА
      Linux: закрашено то, что ОСТАЛОСЬ — полоса уменьшается от полной к пустой.
      Windows: закрашено то, что ПРОШЛО — полоса растёт от пустой к полной.
      Проценты в обеих версиях считаются одинаково (доля прошедшего времени), так
      что 58% на 58% не расходятся — расходится только графика. Символы: Linux
      рисует █ и ░, Windows по умолчанию на Win7+, а на Vista/2008 — ASCII #/-.

   3. КОД ВОЗВРАТА ПРИ Ctrl+C — самое важное для скриптов
      Linux, интерактивный терминал: 130. Документация версии 1.0 была права.
      Linux, без терминала (cron, pipe, перенаправление, служба): 0, потому что в
             тихом режиме скрипт исполняет системный sleep напрямую и свой trap с
             exit 130 не отрабатывает. Обрывок цепочки «sleepv 30s && next» после
             Ctrl+C в этом режиме ПРОДОЛЖИТСЯ — на это стоит опираться осознанно.
      Windows, любой режим: 0 по умолчанию — следующий оператор .bat выполняется,
             запроса «Terminate batch job (Y/N)?» нет. С --strict-cancel: 130,
             цепочка останавливается.
      То есть на Linux код возврата зависит от наличия TTY, на Windows — только от
      явного флага. В PowerShell Ctrl+C в обоих случаях прерывает конвейер по
      правилам самой оболочки: cmd /c "sleepv 30s && next" — способ продолжить.

   4. ВОССТАНОВЛЕНИЕ КУРСОРА
      Linux: tput cnorm в обработчике trap; при SIGKILL курсор может остаться
             спрятанным (лечится tput cnorm или reset).
      Windows: SetConsoleCursorInfo перед выходом по любой своей ветке, включая
             Ctrl+C; при снятии процесса диспетчером задач — то же самое, лечится
             перезапуском консоли или mode con: rate=0 delay=0.

   5. ПАРСЕР ВРЕМЕНИ — РАЗЛИЧИЙ НЕТ
      Обе версии строго одинаковы: s/m/h/d, сумма аргументов, дроби (1.5m, 3.75),
      ведущие нули (007), ноль (0). Одинаково отвергаются с кодом 1: 10x, 1w,
      10s5m, «5 m», 1e3, -5. Разница только в языке сообщения об ошибке (см. п. 7).

   6. ПЕРЕПОЛНЕНИЕ И МАКСИМАЛЬНАЯ ДЛИТЕЛЬНОСТЬ — РАЗЛИЧИЕ ЕСТЬ
      Linux: формального лимита нет; при 999999999999999999999999 арифметика bash
             печатает «syntax error in expression» и пауза становится
             фактически бесконечной.
      Windows: явный отказ «sleepv: duration too large (maximum is 30 days).» с
             кодом 1, максимум 30 суток задан явно.
      Вывод: значения, вычисленные в bash, передавайте с проверкой — лимит
      Windows строже, чем поведение Linux.

   7. ЯЗЫК И КОДИРОВКА ВЫВОДА — РАЗЛИЧИЕ ЕСТЬ
      Linux: русский, UTF-8, псевдографика и символы ⏱ ✓, рамки из ═ и ║.
      Windows: только ASCII и только английский — сознательное решение: консоль
             Windows живёт в кодовой странице OEM (866/1251 для кириллицы),
             растровый шрифт Vista не тянет половину юникода, а лишняя транслит-
             ошибка хуже короткого английского вывода. При --unicode добавляются
             ровно два глифа, █ и ░.
      Следствие: grep по тексту сообщений sleepv между платформами не совпадает —
      ориентироваться надо на коды возврата, а не на строки.

   8. ВЫВОД БЕЗ АРГУМЕНТОВ — ОДИНАКОВО
      Краткая справка в stdout, код 0 (не как у GNU sleep, у которого 1).

   9. НЕИЗВЕСТНЫЕ ОПЦИИ
      Linux отвергает всё, что не --install/--help/--version, включая Windows-опции:
      sleepv --beep 1s → «неверный аргумент: '--beep'», код 1. Windows так же
      не понимает Linux-специфики. Один и тот же вызов с --run/--beep/--msg
      работает только на Windows.

  10. ТИХИЙ РЕЖИМ — ОДНА ЛОГИКА, РАЗНАЯ РЕАЛИЗАЦИЯ
      Linux: [[ -t 2 ]] (stderr привязан к TTY?). Windows: GetFileType
      (STD_ERROR_HANDLE) == FILE_TYPE_CHAR плюс GetConsoleMode. Потоки совпадают:
      stdout чистый, прогресс в stderr, 2>/dev/null глушит бар на обеих платформах.

  11. --install — РАЗНЫЕ ЦЕЛИ И РАЗНЫЕ МЕХАНИЗМЫ
      Linux: /usr/sbin/sleepv, при нехватке прав сам вызывает sudo.
      Windows: C:\Windows\System32\sleepv.exe через UAC, с обходом File System
             Redirector префиксом "\\?\" (иначе 32-битная сборка уедет в
             SysWOW64), с проверкой права Read & Execute для BUILTIN\Users и
             манифестом asInvoker против VirtualStore.
      Windows-дополнения: --uninstall убирает копии из System32 и SysWOW64;
             --install --dir PATH создаёт недостающие уровни каталога сам и, так
             как такая папка не стоит в PATH, прямо об этом предупреждает.

  12. --version
      Linux: версия скрипта 1.0 плюс вывод системного GNU sleep.
      Windows: sleepv 1.1.0, целевая платформа, разрядность бинарника, факт
             прикрепления консоли и строка о статической сборке без redist.

  13. СООБЩЕНИЕ О ЗАВЕРШЕНИИ
      Linux: «✓  Готово! (было: 2m 3s)» (только в интерактивном режиме).
      Windows: «sleepv: finished! (was: 2m 3s)».

  14. КАК ПРОВЕРИТЬ САМОМУ
      bash -c './sleepv 30 >/dev/null 2>&1 & p=$!; sleep 1; kill -INT $p; wait $p; echo $?'
        → 0   (тихий режим, обрыв цепочки не происходит)
      в интерактивном терминале: sleepv 30, затем Ctrl+C, затем echo $? → 130
      ./sleepv 10x; echo $?      → 1 на обеих платформах (текст сообщения разный)
      ./sleepv 999999999999999999999999   → ошибки арифметики bash и вечная пауза
      wine sleepv-x64.exe --install --dir 'C:\\tools'   → устанавливает, создавая папку

── Риск, о котором стоит знать ──────────────────────────────────────────────

   Неподписанный exe, который копирует себя в System32, — это поведение, похожее
   на поведение вредоносного ПО. В корпоративной среде с AppLocker, WDAC или
   правилами Attack Surface Reduction такая установка может быть заблокирована,
   как и запуск скачанного из интернета файла (SmartScreen, Mark-of-the-Web).
   Штатный обходной путь — portable-использование из своей папки или
   --install --dir. Если нужна подпись кода — вопрос к владельцу репозитория.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Требования:
  • bash версии 4.0 и выше (стандартный в Debian/Raspberry Pi OS/Kali)
  • GNU sleep (входит в пакет coreutils — всегда есть в системе)
  • bc или awk (для вычислений — оба есть в любом Debian по умолчанию)
  • tput (для управления курсором — входит в пакет ncurses-bin)

Проверить наличие зависимостей:
    which bash sleep bc awk tput

Поддерживаемые оболочки для вызова:
  ✓ bash    (полная поддержка)
  ✓ sh      (вызов через sh работает, т.к. bash совместим)
  ✓ dash    (вызов работает — shebang указывает на bash)
  ✓ zsh     (вызов как внешней команды работает полностью)

Поддерживаемые терминалы:
  ✓ xfce4-terminal
  ✓ xterm
  ✓ lxterminal
  ✓ gnome-terminal
  ✓ konsole
  ✓ SSH-сессии
  ✓ tmux / screen (прогресс отображается корректно)
  ✓ Вызов из скриптов без терминала (тихий режим)

Единственный сценарий где прогресс может попасть в данные:
  Если ваш скрипт делает:  output=$(команда_вызывающая_sleepv 2>&1)
  Тогда строка прогресса попадёт в переменную output через 2>&1.
  Решение: добавить 2>/dev/null к вызову sleepv внутри такой команды.
  Но это редкий случай — обычные скрипты с этим не сталкиваются.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Как работает обнаружение терминала:
  Команда [[ -t 2 ]] проверяет, привязан ли stderr к TTY (терминалу).
  Если да — включается визуальный режим.
  Если нет (cron, pipe, фон) — запускается оригинальный sleep напрямую.

Как работает прогресс-бар:
  Каждую секунду скрипт перезаписывает текущую строку терминала с помощью
  escape-последовательности \r (возврат каретки) и \033[K (очистка строки).
  Это значит, что прогресс всегда на одной строке — не "прокручивает" экран.

Точность паузы:
  Оригинальный sleep запускается параллельно в фоне.
  Визуальный отсчёт работает поверх него отдельно.
  Итоговая точность паузы — та же, что у системного sleep.
  Визуальный счётчик считает с погрешностью ±1 секунда (это норма).

Где находится прогресс-бар в потоках вывода:
  stdout (поток 1) — чистый, как у оригинального sleep
  stderr (поток 2) — прогресс-бар и таймер

Поведение при Ctrl+C:
  Скрипт перехватывает сигнал INT, завершает фоновый sleep,
  восстанавливает курсор (tput cnorm) и выходит с кодом 130.
